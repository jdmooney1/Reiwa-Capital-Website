# tools/maps

Builds the About-page focus maps: `assets/maps/{london,amsterdam}-{wide,tall}.svg`, `*-focus.js`, and the label, legend, note and alt-text markup in `about.html` and `ja/about.html`.

```
MAP_DATA=/path/to/extracts python3 tools/maps/build.py
```

Needs Python 3, `shapely` 2.x and `pyproj`. A rebuild from the same extracts is byte-identical.

`MAP_DATA` holds these files (sources and boundary dates: `docs/map-geography.md`):

- `wards_E09000001/07/12/19/20/22/28/30/33.json`, `city_of_london_lad.json`: ONS ward and district boundaries (December 2013)
- `blackmad_amsterdam.geojson`: Gemeente Amsterdam buurtcombinaties (legacy set)
- `ams-cbs.geojson`: CBS Wijk- en buurtkaart 2022, buurten
- `cbs2022_amsterdam_buurt.geojson`, `cbs2022_amsterdam_wijk.geojson`: the same CBS layers, Amsterdam only (audit only)
- `{london,amsterdam}_segment.geojson`, `_land_use.geojson`, `_water.geojson`: Overture Maps release 2026-08-19.0 extracts for the two bounding boxes. These are **replacement inputs** regenerated by `extract_overture.py` after the originals were lost (`python3 tools/maps/extract_overture.py OUTDIR [london|amsterdam]`; needs `pyarrow`, reads the public S3 bucket); `sources.json` pins the replacements and keeps the original hashes.

`sources.json` pins every input by SHA-256 and vintage (source-file integrity verification: a matching hash shows the file is the pinned one, not that its boundaries are right). `build.py` stops if an input differs (set `ACCEPT_NEW_SOURCES=1` only after review): the focus areas are Reiwa's market definitions, so a new ward or boundary set must not move them silently.

`audit.py` reproduces the figures in `docs/map-geography.md` (areas, street support, overlaps with the CBS and legacy units, Canal Belt and Aldwych figures) and writes `docs/map-audit.json`. It also reads `cbs2022_amsterdam_buurt.geojson` and `cbs2022_amsterdam_wijk.geojson` (CBS 2022, Amsterdam only).

`coverage_rules.py` cuts every area back to the retained coverage plus two recorded rules (seam within 13 m of two retained areas; recorded enclosed gaps up to 0.25 ha), so final coverage is the retained coverage plus the recorded seam and gap allowances only (the cleanup allocates retained ground between areas, and nothing else is left in); `check_coverage.py` (run inside `build.py`, or alone, `--selftest` to prove it fails) enforces it with a tolerance of 0.5 m width / 1 m2; `coverage.py` (run by `audit.py`) compares the coverage union of the final areas with the retained coverage and writes `docs/map-coverage-union.md`. `london_fragments.py` decides every ward fragment and detached part of 0.5 ha or more by named streets (the build stops on one that is not listed); `crops.py` draws review crops for `audit.py` (`CROPS_DIR=<dir>`); `docs/london-ward-fragments.md` is generated by `audit.py`.

Generated files (`__pycache__`, `*.pyc`) are ignored by the repository `.gitignore`; run with `PYTHONDONTWRITEBYTECODE=1`.

Modules: `boundaries.py` (street cuts, masks), `clean.py` (dissolve, seam and gap handling), `geometry.py` (the approved areas), `render.py` (SVG frames, label and leader placement), `pages.py` and `focus_js.py` (write the repository files).

Labels are laid out for the narrowest width each frame is shown at (wide 420 px, tall 320 px) and share positions between English and Japanese. A label can carry a `fixed` placement per frame in `render.py` (found by exhaustive search and checked on the rendered pages, see `docs/map-geography.md`, "Labels").

Zuidas is Reiwa's selected Noord + Zuid footprint (CBS 2022 buurten Zuidas Noord and Zuid), not an official boundary; the official description states approximately 245 ha and no further CBS units are added to approach it.
