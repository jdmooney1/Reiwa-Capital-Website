0Scope note — two requested items don't exist in this build

Track Record page and component, and a custom 404 / error state, appear in the audit brief but nowhere in the project. The live information architecture is five pages — Home, About, Approach, Investment Focus, Contact — plus an unlisted Privacy notice; there is no track-record.html and no 404 template. Rather than invent findings for a page that doesn't exist, this is flagged as a scope question: a Track Record page (naming realised deals, returns or assets) would sit in direct tension with the brief's confidentiality rule — "Never name a deal, client, or figure" — and reads more like a principal/direct-ownership firm's page than an investor-side adviser's (see P0-1). Worth resolving alongside P0-1, not before it. The 404 gap is listed as Optional (O-2) since most static hosts supply a default.

P0-1P0Two incompatible business models are on record

Route All  ·  Language Both  ·  Viewport N/A  ·  Component Sitewide positioning
Description

The project brief (CLAUDE.md) describes a firm placing Japanese capital into UK/Dutch buildings held in direct ownership — a principal. The built site consistently describes an investor-side coordinator that holds no discretionary authority and explicitly places property managers among third-party specialists. Every other copy question in this register depends on which is correct.

Evidence

Approach's Operating Model: "Investment authority remains with the investor." vs. CLAUDE.md: "placing Japanese private capital into UK and Dutch buildings, held in direct ownership."

Recommended correction

Confirm which model governs; retire the losing language from whichever document is wrong.

Risk of correction

None to fix directly — but the answer changes P0-2, P1-3, §0's Track Record question, and potentially other copy not yet flagged.

P2-4P2Scroll-reveal is implemented three separate times

Route Approach, Investment Focus, sitewide via shell.js  ·  Language Both  ·  Viewport N/A  ·  Component Scroll-entry fade-in
Description — shared cause

One generic engine (shell.js → setupReveals() + data-reveal/is-in, timed off --dur-4) coexists with two independent, hand-rolled copies of the same idea: Approach's .stage-row script (reveal/in classes, hardcoded 700ms) and Investment Focus's .chapter script (same pattern, separate code). All three guarantee a forced-visible fallback, so nothing is ever left hidden — this is a maintainability/consistency finding, not a broken-content one.

Recommended correction

Consolidate onto the one generic engine, or accept the duplication as intentional per-page tuning — either way, worth a decision so a future edit to timing doesn't get made in only one of the three places.

P3-2P3Operating Model reveal fades opacity and position on two different clocks

Route Approach  ·  Component .om-group/.om-spine reveal
Description

The shared reveal engine's base rule (editorial.css) animates both opacity and transform on --dur-4 (380–440ms). Approach's own inline style separately declares .om-group, .om-spine { transition: opacity 260ms var(--ease-out); } — equal specificity to [data-reveal], later in source order, so it wins for opacity specifically while transform stays on the original clock. The two properties of one reveal now settle at different times.

Recommended correction

Drop the hardcoded 260ms opacity transition from .om-group, .om-spine (the hover/focus dim effect can reuse a differently-named transition, or simply share --dur-4).
